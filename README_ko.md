## 🚀 핵심 전략: 조기 업로드(Early Uploading) 및 백그라운드 지속성

게시 버튼을 누른 후 나타나는 "대기 화면"을 제거하기 위해 본 프로젝트는 다음과 같은 전략을 채택했습니다.

1. **조기 업로드(Early Uploading)**: 사용자가 글 작성을 마칠 때까지 기다리는 대신, 미디어 선택이 완료되는 즉시 백그라운드에서 이미지 업로드를 시작합니다.
2. **백그라운드 지속성 (WorkManager)**: Android의 `WorkManager`를 활용하여 사용자가 앱을 종료하거나 OS에 의해 프로세스가 종료되더라도 업로드 프로세스가 끝까지 완료되도록 보장합니다.

---

## 🛠 기술적 구현: 2단계 Worker 체이닝

업로드 프로세스는 로컬 데이터베이스(`FeedUploadStatus`)를 통해 동기화되는 두 개의 독립적인 `CoroutineWorker` 클래스로 구성됩니다.

### 1. UploadFeedImagesWorker
* **역할**: Firebase Storage로의 다중 이미지 병렬 업로드를 처리합니다.
* **병렬 최적화**: `flatMapMerge(concurrency = 10)`를 사용하여 최대 10장의 이미지를 동시에 업로드함으로써 전체 업로드 시간을 대폭 단축합니다.
* **순서 보장 (Order Preservation)**: 병렬 처리 중에도 이미지가 선택된 원래 순서가 엄격하게 유지되도록 인덱싱 및 `sortedBy` 로직을 구현했습니다.
* **회복 탄력성**: 불안정한 네트워크 환경을 유연하게 처리하기 위해 `IOException`에 대한 `retry(2)` 정책을 포함합니다.

### 2. UploadFeedContentWorker
* **역할**: 생성된 `downloadUrl` 목록과 사용자의 캡션을 결합하여 데이터베이스에 최종 피드 항목을 등록합니다.
* **반응형 상태 관찰**: `transformWhile`을 사용하여 로컬 DB를 반응적으로 관찰합니다. 업로드 상태가 `IMAGE_SUCCESS`에 도달할 때까지 기다린 후 즉시 최종 메타데이터 제출을 트리거합니다.

## 🔄 시퀀스 다이어그램 및 흐름

1. **이미지 선택**: `UploadFeedImagesWorker`가 즉시 대기열에 추가됩니다. 로컬 상태가 `LOADING`으로 전환됩니다.
2. **캡션 작성**: 사용자가 타이핑하는 동안 이미지는 백그라운드에서 업로드됩니다. 완료되면 상태가 URL 목록과 함께 `IMAGE_SUCCESS`로 업데이트됩니다.
3. **게시 버튼 클릭**:
    - 이미 이미지가 업로드된 상태(`IMAGE_SUCCESS`)라면, `UploadFeedContentWorker`가 게시물을 즉시 완성합니다.
    - 업로드가 진행 중이라면, Worker는 로컬 DB를 관찰하다가 URL이 준비되는 순간 자동으로 게시를 마무리합니다.

## 💡 왜 WorkManager인가?
- **지속성(Persistence)**: 앱 종료나 시스템 재부팅 후에도 작업이 유지되어 업로드 성공률을 높입니다.
- **제약 조건(Constraints)**: 기기가 유효한 네트워크에 연결되어 있을 때만 실행되도록 구성할 수 있습니다.
- **가시성(Visibility)**: UI에서 `WorkInfo`를 관찰하여 사용자에게 실시간 피드백(예: 프로그레스 바, 성공/실패 알림)을 제공할 수 있습니다.
